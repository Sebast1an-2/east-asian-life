# V0.2阶段4：中年人生与跨年龄回声

保留原50个事件，新增18个候选，总数68。新内容集中36～59岁，不保证每局全部发生。
所有新增事件都不标记Major：这里是可以延期的选择，没有提前排定必须发生的出生或退休。
成为父母的卡片是再次确认意愿；只有玩家选择后才在本年度记录实际出生。

## 中年事件清单

年龄包含两端；具体条件在events-middle.js，继续复用Player、History、Tags和状态。

除了标明冷却的事件，其余只发生一次。mid_decision_echo隔8年可以再遇到另一位晚辈，
让孩子成长后也有自己的方向讨论机会；不是每年追问同一个决定。
亲子年龄不足时，成绩和红包回声先等待；孩子已经超过对应年龄则不安排不合年龄的场景。
无孩子可以进入晚辈版本，不必先生成孩子。其他回声并不绑定生育、婚姻或房产。

## 9类跨年龄回声的真实来源

每类均测试至少两个不同早期choice产生不同文字。历史查询使用真实eventId/choiceId，
不凭标签推测过去；抓周只说照片和大人的解释，不假装玩家记得一岁时的想法。

| 回声主题 | 早期具体选择 | 可继续读取的青年经历 | 中年的意义变化 |
|---|---|---|---|
| 95分 | score95/promise、celebrate | home/talk | 从被问的人变成先开口回应孩子或晚辈的人 |
| 兴趣 | interest/math、art | old_album/draw、keep | 不再为升学加分，重新分配自己的时间 |
| 红包 | red_envelope/entrust、budget | young_salary_echo/share、buffer | 从交钱或争取预算，变成帮助晚辈学习支配权 |
| 手机与在线 | phone_request/accept、negotiate | boss_message/reply、morning | 从接收消息的人变成能协调年轻同事边界的人 |
| 排名与比较 | ranking/chase、review；neighbor/learn、mud | young_ranking_echo/compete、own_scale | 自己也成了别人家的大人，决定如何衡量、如何问别人 |
| 亲戚问答 | relatives_child/perform、ask_back | relatives_adult/explain、redirect | 从回答者变成提问者，选择规划关心或私下沟通 |
| 替人决定 | first_plan/pen、toy；major/safe、like | young_decision_echo/own_plan、joint_plan | 自己拥有经验之后，决定建议与替人决定之间的边界 |
| 老朋友 | best_friend/keep、goodbye | 青年保留真实老友History，不要求额外青年事件 | 重新认识对方现在的生活，不预设疏远就是失败 |
| 春节 | young_holiday/home、stay；spring_home/gift、cook | 这些选择本身发生在青年时期 | 从回答回来与否，变成组织相聚并接纳别人的安排 |

青年经历只在真实存在时追加，缺少它不会编造。回声不是相同选项再问一次，
重点是回应、照顾、协调或支配权发生变化。重复习惯、主动改变和折中都有成本与收益。

## 三个从出生正常抽取的实际例子

下面来自middle-tests.cjs的随机种子1完整人生，实际经过正式年度引擎。

1. 8岁score95/celebrate，为努力说话 → 21岁home/keep，收好旧试卷、肯定自己 →
   40岁mid_score_echo/listen，面对亲戚晚辈的95分，先听努力再谈下一步。
   卡片读取的是“可是我已经很努力了”，不是另一个选择的满分承诺。
2. 13岁interest/art，坚持画画 → 28岁old_album/draw，重新拿起画笔 →
   36岁mid_interest_echo/practice，为画画保留固定时间。
   另一条math历史会说把画画的位置让给数学；这两种文案已分别验证。
3. 12岁phone_request/accept，接受随时回应 → 24岁boss_message/reply，接下临时任务 →
   37岁mid_boundary_echo/wait，轮到协调任务时把消息留到白天，承担延期代价。

这些是可能的人生，不是固定年龄表；窗口内仍按现有分类、priority、weight选择。

## 有孩子与无孩子

真实青年准备意愿 → mid_parenthood再次确认 → begin选择 → child.hasChild=true，
birthYear由引擎记为当前年份。工作、关系、住房其他状态不会自动改变。
拒绝、暂缓或无准备意愿都不生成孩子；现有孩子也不重复生成。
暂缓标签保留给将来的重新准备内容，本轮不建设完整生育系统。

有孩子可遇到亲子成绩、红包支配、自己对比较的示范、成年孩子的方向建议；
是否使用亲子文字会检查孩子年龄。一个实际年度续接测试：36岁出生 → 42岁红包 →
44岁孩子8岁时出现95分 → 57岁孩子21岁时参与方向讨论。

无孩子同样有晚辈成绩、红包和饭桌、年轻同事边界、个人兴趣、老友、原生家庭、
春节组织、居住预算与个人时间。相伴但不登记也有生活安排；单身不自动等于孤独。
两条路线都能通过代际回应进入mid_response，保留同等重要的回声体验。

中年选择会继续留下实际影响：

- 成绩、红包、饭桌、方向建议的不同标签，改变mid_response中的反馈。
- 画画、老友、比较尺度、另约相聚，改变之后mid_daily的情境。
- 深夜消息约定，改变后续职业事件中的排期文字。
- 高压转平衡会关闭高压事件、打开专业工作；待业重新就业会重建工作开始年份。

## 最小展示补充与存档

descriptionDetails是可选数组，每项只有conditions和text，满足条件就追加到description。
主条件与文案条件共用matchesConditions，也共用字段、状态、年龄与历史引用校验。
没有新剧情脚本、NPC、路线分数或独立调度器。

childAge范围来自现有childAge(player)。allowNoChild:true允许无孩子走晚辈版本，
默认必须有年龄合适的孩子；不会写死“40岁有孩子”。
选择时History可选保存eventDescription文本，保留当时展示的文字，刷新不会因
当前标签或状态变化而重新改写过去的卡片。没有属性快照，存档格式仍为version 3，
没有eventDescription的旧历史仍合法。年度上限、同年追加、冷却、旧存档升级保持原机制。

## 验证结果

运行node tests.cjs，自动包含旧8/28事件、阶段1/2、青年50事件和中年68事件检查。
也可以单独运行node middle-tests.cjs。

- 全库68事件：0格式/引用错误，0警告；警告机制仍保留。
- 9类回声各测两个早期choice、缺失历史、有孩子/无孩子，以及不同成年回应。
- 128轮从出生到80岁的完整模拟，36～59岁最长连续空白0年。
- 12组中年状态各8轮：高压、平衡、转向、已婚有孩子、已婚无孩子、不婚伴侣、
  单身、自有住房、租住、保留兴趣、放弃兴趣、待业；最长连续空白均0年。
- 完整历史的这些状态，每局至少12～15种中年候选、8～9类回声；平衡路线至少14种。
  已婚无孩子与有孩子组都至少15种，未发现无孩子内容明显减少。
- 独立测试验证青年真实准备→出生→孩子成长→亲子回声，新增18个候选均有实际触发路径。
- 原8/28库的160轮、青年库的560轮、年度节点与页面刷新回归保留并通过。
- 68事件页面在选择前后均重载脚本，核对文字、完整状态、历史和年度进度。

覆盖不是所有组合的穷举，不保证每局集齐回声。未发生过对应事件的人仍有独立生活候选。
本阶段不扩充60岁以上剧情，不制作新寿命、最终总结、父母死亡或完整NPC系统。
